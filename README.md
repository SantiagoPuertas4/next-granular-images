# next-granular-images

Build-time image optimisation for Next.js: AVIF/WebP variants with separate quality settings, blur placeholders, art direction and typed image modules, generated by a CLI on top of sharp.

[![npm version](https://img.shields.io/npm/v/next-granular-images.svg)](https://www.npmjs.com/package/next-granular-images)
[![CI](https://github.com/SantiagoPuertas4/next-granular-images/actions/workflows/ci.yml/badge.svg)](https://github.com/SantiagoPuertas4/next-granular-images/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

## The problem

Serving images well from a Next.js site means, for every image: encoding AVIF and WebP at several widths, writing `<picture>`/`<source>` markup with matching `srcset` and `sizes`, switching files per breakpoint for art direction, producing a blur placeholder, and keeping all of it in sync when a source file changes. `next/image` does this at request time and needs an image server, which a static export (`output: 'export'`) does not have.

`next-granular-images` does it once, at build time. It reads your source images, writes the variants into `public/`, and generates a TypeScript module per folder that exports each image as a typed object. A React component renders that object as a `<picture>` element.

## Install

```bash
npm install next-granular-images sharp
# or
pnpm add next-granular-images sharp
```

Requirements:

- Node.js `>=20.19.0`
- Peer dependencies: `sharp` `^0.33.0 || ^0.34.0`, `react` `>=18.0.0`, `next` `>=13.0.0`

## Quick start

**1. Create the config file.**

```bash
npx next-granular-images init
```

This writes `next-granular-images.config.ts` in the project root. The template reads source images from `src/assets` and writes variants to `public/next-granular-images`.

**2. Add images and optimise them.**

```text
src/assets/
  logo.png
  home/
    hero-desktop.jpg
    hero-mobile.jpg
```

```bash
npx next-granular-images optimize
```

Run it before `next build` (for example in a `prebuild` script). It writes:

```text
public/next-granular-images/...                      # AVIF/WebP variants + a cleaned copy of each original
src/generated/next-granular-images/config.d.ts       # breakpoint names, for type checking
src/generated/next-granular-images/images.gen.ts     # images in src/assets/
src/generated/next-granular-images/home/images.gen.ts  # images in src/assets/home/
```

**3. Import the generated module.** Each image is exported under its file name (non-identifier characters become `_`), plus a `<name>_blur` string with its placeholder:

```ts
// src/generated/next-granular-images/home/images.gen.ts (excerpt)
const __granularBreakpoints = {"sm":640,"md":768,"lg":1024,"xl":1280} as const;

export const hero_desktop = {
  src: "/next-granular-images/home/hero-desktop-b110286a-2e77be58/hero-desktop-b110286a-2e77be58.jpg",
  width: 1200,
  height: 800,
  dominantColor: "rgb(200,24,24)",
  breakpoints: __granularBreakpoints,
  variants: {
    avif: "/next-granular-images/home/hero-desktop-b110286a-2e77be58/hero-desktop-b110286a-2e77be58-16.avif 16w, ...",
    webp: "/next-granular-images/home/hero-desktop-b110286a-2e77be58/hero-desktop-b110286a-2e77be58-16.webp 16w, ...",
  }
} as const;

export const hero_desktop_blur = "data:image/jpeg;base64,...";
```

**4. Render it.** Add `<GranularBlurFix />` once in the root layout, then use `<NextGranularImage>`:

```tsx
// app/layout.tsx
import { GranularBlurFix } from 'next-granular-images';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        <GranularBlurFix />
        {children}
      </body>
    </html>
  );
}
```

```tsx
// app/page.tsx
import { NextGranularImage } from 'next-granular-images';
import { hero_desktop, hero_desktop_blur } from '@/generated/next-granular-images/home/images.gen';

export default function Page() {
  return (
    <NextGranularImage
      src={hero_desktop}
      alt="Team at work"
      placeholder={hero_desktop_blur}
      sizes="100vw"
      className="w-full"
      loading="eager"
      fetchPriority="high"
    />
  );
}
```

The `@/` import assumes the default Next.js alias `"@/*": ["./src/*"]`; use a relative path otherwise. Keep the types folder inside your `tsconfig.json` `include` so `config.d.ts` is picked up.

## Configuration

`next-granular-images.config.ts` (or `next-granular-images.config.js`) in the project root, default-exporting a `GranularImagesConfig`. A missing config file is an error.

| Key | Type | Default when omitted | `init` template |
| --- | --- | --- | --- |
| `qualities.avif` | integer 1-100 | none | `60` |
| `qualities.webp` | integer 1-100 | none | `85` |
| `effort.avif` | integer 1-9 | none | `9` |
| `effort.webp` | integer 1-6 | none | `6` |
| `breakpoints` | `Record<string, number>` | `{ sm: 640, md: 768, lg: 1024, xl: 1280 }` | same |
| `deviceSizes` | `number[]` | `[640, 750, 828, 1080, 1200, 1920, 2048, 3840]` | `[400, 500, 640, 750, 828, 1080, 1200, 1920, 2048, 3840]` |
| `imageSizes` | `number[]` | `[16, 32, 48, 64, 96, 128, 256, 384]` | same |
| `concurrency` | positive integer | `4` | `4` |
| `minSizeToOptimize` | number (KB), `>= 0` | `0` | `0` |
| `blurSize` | integer 4-64 (px width) | `10` | `10` |
| `blurQuality` | integer 1-100 | `50` | `100` |
| `paths.input` | string | `'public'` | `'src/assets'` |
| `paths.output` | string | `'public/next-granular-images'` | same |
| `paths.types` | string | `'src/generated/next-granular-images'` | same |
| `exclusions` | `string[]` | `['.ico', '.xml', '.webmanifest', '.svg', '.webp', '.avif']` | same |

Rules enforced at load time:

- At least one of `qualities.avif` / `qualities.webp` is required, and each quality needs the matching `effort` (and vice versa). Only the formats you configure are generated.
- `breakpoints` values, `deviceSizes` and `imageSizes` must be positive integers in strictly ascending order.
- `paths.output` must be a folder inside `public/`, because generated URLs are relative to it.
- `exclusions` match the end of the file name, so they can be extensions (`.svg`) or suffixes (`.min.png`).
- `concurrency` is the number of images encoded in parallel. It is the only key that does not affect the cache.

Supported source formats: `.png`, `.jpg`, `.jpeg`, `.webp`, `.avif`, `.tiff`, `.gif`, `.svg` (`.webp`, `.avif` and `.svg` are excluded by default).

## CLI

```bash
npx next-granular-images <command> [flags]
```

| Command | Flag | Effect |
| --- | --- | --- |
| `init` | | Creates `next-granular-images.config.ts`. Skips creation if it already exists. |
| | `--build [prod\|fast\|dev]` | Then runs `optimize` in that mode (`prod` when no mode is given). |
| `optimize` | | Encodes every changed image, reuses cached ones, and regenerates `config.d.ts` and all `images.gen.ts` files. |
| | `--fast` | WebP only, quality 15, effort 1. For quick local iterations. |
| | `--dev` | Halves the configured qualities and sets every effort to 1. |
| | `--report` | Prints an estimated per-breakpoint savings table (closest AVIF, else WebP, variant vs the original file). |
| `generate` | | Regenerates the type files from existing output, without encoding. Needs a previous `optimize`. |
| | `--breakpoints` | Only `config.d.ts`. |
| | `--images` | Only the `images.gen.ts` files. |
| `clean` | | Deletes the output folder and the types folder. |
| | `--image`, `--images` | Deletes the output folder and every `images.gen.ts`; keeps `config.d.ts`. |
| | `--breakpoints` | Deletes only `config.d.ts`. |
| | `--all` | Deletes the output folder, the types folder and the config file. |

`clean` only removes folders inside the project whose path contains `next-granular-images`; anything else is skipped with a warning. If the config file is missing or invalid, `clean` warns and uses the default paths (`public/next-granular-images`, `src/generated/next-granular-images`).

Exit codes are `0` on success and `1` when:

- the command is missing or unknown;
- `optimize`, `generate` or `init --build`: the config file is missing or invalid, or `paths.output` is not inside `public/`;
- `optimize`: `paths.input` does not exist, there are duplicate images (identical content, or two files with the same name and different extensions in one folder), or any image fails to process. Types are still written for the other images, and a failed image keeps its previous output and export;
- `generate`: the output folder does not exist, source images exist but none has a meta file, or any image has a missing, corrupt or outdated meta file. The `images.gen.ts` of that image's folder is left untouched;
- `init --build`: the `optimize` run fails.

`clean` exits `0` even when it skips a path or cannot load the config; `init` exits `0` when the config file already exists.

Environment variables: `LOG_LEVEL` (`debug`, `info`, `success`, `warn`, `error`; default `info`) and `QUIET=true` (errors only).

## Components

### `<NextGranularImage>`

Renders a wrapper `<div>` with an optional blur layer and a `<picture>`: one AVIF and one WebP `<source>` per image, and an `<img>` pointing at the original file as the fallback.

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `src` | `GeneratedImage \| ArtDirectionSrc` | required | A generated image, or an art-direction object (below). |
| `alt` | `string` | required | |
| `sizes` | `string` | none | Forwarded to every `<source>` and the `<img>`. Without it the browser assumes `100vw`. |
| `placeholder` | `string \| null` | none | The `<name>_blur` data URL. Omit it for no blur layer. |
| `className` | `string` | none | Applied to the **wrapper** (layout, position, size). |
| `style` | `CSSProperties` | none | Applied to the **wrapper**, merged over its defaults. |
| `imgClassName` | `string` | none | Applied to the inner `<img>` (for example `object-fit`, border radius). |
| `imgStyle` | `CSSProperties` | none | Applied to the inner `<img>`, merged over its defaults. |
| `loading` | `'lazy' \| 'eager'` | `'lazy'` | |
| `decoding` | `'async' \| 'sync' \| 'auto'` | `'async'` | |
| `fetchPriority` | `'high' \| 'low' \| 'auto'` | none | Passed in the form the running React version expects. |
| `customBreakpoints` | `Record<string, number>` | none | Overrides breakpoint widths for art direction. |

Any other `<img>` attribute is forwarded to the `<img>`.

Wrapper defaults: `position: relative` (unless `className` contains `absolute` or `style.position` is `absolute`), `display: inline-block`, `line-height: 0`, `vertical-align: top`. The `<img>` defaults to `width: 100%` and, for a single image, the `width`/`height` attributes and an `aspect-ratio` from the source.

### Art direction

Pass an object keyed by breakpoint name, with a required `default`:

```tsx
import { hero_desktop, hero_mobile, hero_desktop_blur } from '@/generated/next-granular-images/home/images.gen';

<NextGranularImage
  src={{ default: hero_mobile, md: hero_desktop }}
  alt="Team at work"
  placeholder={hero_desktop_blur}
  sizes="100vw"
  className="block w-full h-[60vh]"
  imgStyle={{ height: '100%', objectFit: 'cover' }}
/>
```

Each breakpoint entry becomes `<source media="(min-width: …px)">` elements, widest first; `default` applies below the smallest one used. Breakpoint widths come from, in increasing priority: built-in defaults (`sm` 640, `md` 768, `lg` 1024, `xl` 1280), the `breakpoints` embedded in the generated images (your config), and `customBreakpoints`. `config.d.ts` restricts the allowed keys to your configured breakpoint names.

In art-direction mode the `<img>` gets no `width`/`height` or `aspect-ratio`, because the files can have different proportions. Reserve the space with CSS on the wrapper to avoid layout shift.

### Placeholder and `<GranularBlurFix>`

With `placeholder`, a blurred background layer sits behind the image. The `<img>` is always visible and paints over it, so no JavaScript is needed to show the image. `<GranularBlurFix />` (a client component, included once in the root layout) fades the blur layer out when each image loads, which matters for images with transparency, where the blur would otherwise stay visible behind them.

## How it works

1. **Scan.** Lists files under `paths.input` (skipping `paths.output` and `exclusions`), and fails on duplicate content or name collisions.
2. **Hash.** Each image gets `<fileHash>-<configHash>`: the first 8 hex characters of the SHA-256 of the file, and of the output-affecting config (everything except `concurrency`) salted with the package version.
3. **Cache.** Outputs of the same image with a different hash are deleted. If a valid meta file and the copied original for the current hash exist, the image is skipped; otherwise it is encoded. Changing the config, switching between `--fast`/`--dev`/normal, or upgrading the package re-encodes everything.
4. **Encode.** With sharp: apply EXIF rotation, convert to sRGB, and encode each configured format at every width in `deviceSizes` ∪ `imageSizes` that is not larger than the source (no upscaling). The blur placeholder is resized to `blurSize` px wide, as JPEG, or WebP for images with alpha. The original is written for the `<img>` fallback in its own format with no EXIF/XMP/IPTC metadata (camera data, GPS position), EXIF rotation applied and the ICC colour profile kept. An original that has none of that metadata and needs no rotation is copied byte for byte. Otherwise it is re-encoded: JPEG, lossy WebP and AVIF at high quality (retried once at a lower quality if the result would be more than 5% larger than the source), lossless WebP, PNG and TIFF losslessly (palette PNGs stay palette PNGs). Files smaller than `minSizeToOptimize` KB get only that cleaned original, with no variants and no placeholder. GIFs are copied as-is (re-encoding would drop animation), metadata included; SVGs are copied as-is.
5. **Generate types.** One `images.gen.ts` per source folder, plus `config.d.ts`. `images.gen.ts` files for folders that no longer have images are removed. Output files that no longer belong to any image are reported, not deleted; `clean` removes them.

Output layout for `src/assets/home/hero-desktop.jpg`:

```text
public/next-granular-images/home/
  hero-desktop-b110286a-2e77be58.meta.json
  hero-desktop-b110286a-2e77be58/
    hero-desktop-b110286a-2e77be58.jpg          # cleaned original (the <img> fallback)
    hero-desktop-b110286a-2e77be58-16.avif
    hero-desktop-b110286a-2e77be58-16.webp
    ...
    hero-desktop-b110286a-2e77be58-1200.avif
    hero-desktop-b110286a-2e77be58-1200.webp
```

The meta file stores dimensions, the placeholder and variant paths relative to the output folder. `generate` rebuilds the type files from these meta files.

## Benchmark

In a lab measurement on 7 pages of a production Next.js site (static export, headless Chromium, AVIF served, transferred image bytes only), with the 7 pages combined per viewport, the library downloaded **98.39% to 99.61% fewer image bytes than the unprocessed originals** and **47.43% to 88.76% fewer than one hand-exported 1920 px JPEG (q80) per image**. Per individual page and viewport, the ranges are **95.41% to 99.83%** vs the originals and **18.62% to 91.42%** vs the hand-exported JPEG. The originals baseline is inflated by very large source files; the JPEG baseline is closer to a careful manual export. Load time and Core Web Vitals were not measured.

Method, per-page results, limitations and raw data: [docs/benchmark.md](docs/benchmark.md).

## Limitations

- **Build time only.** Local files only; no remote images, no on-demand resizing. Run `optimize` whenever images change.
- **Encoding cost.** AVIF at high effort is slow, and every image is encoded at every applicable width in each format. The first build of a large image set can take a while; use `--dev` or `--fast` while iterating and tune `concurrency`.
- **Output must live under `public/`.** A copy of each original is written there too, so it is publicly downloadable as the fallback. EXIF/XMP/IPTC metadata is stripped from it, except for GIFs, which are copied unchanged. Originals that carried metadata or an EXIF rotation are re-encoded, so lossy ones (JPEG, lossy WebP, AVIF) are not byte-identical to the source.
- **Formats.** `.heic` is not supported. GIFs are copied without variants or placeholder (re-encoding would drop animation). SVGs are excluded by default.
- **Blur fade needs JavaScript.** Without it, images still display, but the blur layer is not faded out.
- **You write `sizes`.** The component does not infer it; without it the browser assumes `100vw` and may pick larger files than needed.
- **HTML weight.** `srcset` strings and inline base64 placeholders are part of the rendered HTML.
- **Not a `next/image` drop-in.** It is a separate component with its own props.
